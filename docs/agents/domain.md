# Domain docs

Intcad uses a single context. Before exploring the codebase, read the root `CONTEXT.md` and any relevant ADRs under `docs/adr/`. If either is missing, proceed without calling it out or scaffolding it. `/domain-modeling` creates these docs as terms and decisions are settled.

Use glossary terms — the terms defined in the root `CONTEXT.md` — in issue titles, proposals, hypotheses, and test names. If a term is missing, check whether an existing term fits before noting a gap for `/domain-modeling`.

If a proposal contradicts an ADR, name the ADR and explain why the decision is worth reopening.
